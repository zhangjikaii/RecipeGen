# 食谱推荐与验证

## 输入

用户的食材库存、时间上限、忌口、是否允许缺少食材，以及需要的推荐数量。

## 执行

1. 在 RecipeGen 项目目录工作，阅读 README，确认当前是示例数据还是真实数据、规则模式还是配置了 LLM。
2. 运行 `python -m recipegen demo --question '用户的原始需求'`。只有配置了模型且用户需要模型生成时才追加 `--llm`。
3. 检查结构化约束、检索到的菜谱、证据来源、条件验证结果和运行模式。
4. 依据返回的菜谱整理推荐。保留已有步骤、来源标识和缺少食材信息，不编造图谱中不存在的事实。
5. 若无匹配，说明是哪类约束导致无结果。提出可以调整的条件，不擅自放宽用户的忌口或食材要求。
6. 生成 Markdown 报告：原始需求、解析条件、推荐及理由、做法、来源、验证结果、数据与模型模式。

## 验证

- 每条推荐都要能对应一个真实检索结果和来源。
- 时间、禁用食材、辣味和库存约束都要检查；缺少属性不等于已满足条件。
- 报告结果必须和程序的验证结果一致；LLM 失败时如实说明回退情况。
- 示例数据中的通过率不能写成真实用户图谱或真实模型的性能。

## 交付

用户请求保存时，将报告写入 `reports/`，附上复现命令。请求评测时运行 `python -m recipegen evaluate --output reports/evaluation.json`，引用报告中实际产生的指标并说明数据范围。

本 Skill 是可复用的操作流程资产。它不代表已经实现模型自主规划或自动选择工具。
