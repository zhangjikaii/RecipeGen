# RecipeGen 演示数据与手工评测用例

**源码发布中保留的 `example_graph.json` 和 `evaluation_cases.json` 是手工合成示例，不是真实 RecipeGen 图谱的导出。** 真实语料、图谱 CSV、媒体和向量检查点不随源码发布。后续构建脚本会在本目录生成 `test_graph/`、`graphrag/` 等产物，不能将生成的真实语料与下面的人工示例混为一谈。

真实图谱重建顺序见 [README](../README.md)和 [测试集图谱构建](../docs/测试集图谱构建.md)，索引方法见 [GraphRAG 设计](../docs/GraphRAG设计.md)。第三方数据与模型的授权以原来源为准，本次发布不重新授予相关使用权。

- `example_graph.json`：20 道人工编写的简化演示菜谱，9 条明确的食材同义词映射。每道菜谱有稳定 ID、主料、调料、演示时间、标签、步骤和 `demo:` 来源 ID。数据元信息标注 `is_demo: true`、`source: manual-demo` 与 `CC0-1.0`。
- `evaluation_cases.json`：50 个人工编写的断言例子，其中 `structured/` 类别 32 个、`nl/` 类别 18 个。用例及预期结果没有由 LLM 生成或判分。

## 使用约定

1. `ingredients` 只存主料；`seasonings` 单独存调料。默认库存匹配只要求全部主料属于 `available_ingredients`；不要求调料在用户库存中。排除食材仍同时检查主料与调料，因此“不能放盐”会过滤含盐菜谱。
2. 同义词采用明确、单跳映射，如“西红柿 → 番茄”；不把含义过宽的“蛋”或生“大米”映射到“鸡蛋”或熟“米饭”。“蘑菇”与“香菇”保留为不同主料。
3. `max_minutes: null` 表示不设时间上限；有上限时等于上限的菜谱可以匹配。`required_tags` 必须全部满足，`辣` 与 `不辣` 为互斥标签。“素食”是示例的检索标签，本数据仅为不含肉类、海鲜与鸡蛋的菜谱设置该标签。
4. 默认 `allow_missing: false`。只有显式允许缺料时才能返回缺主料的菜谱，并应返回 `missing_ingredients`；这里不另设缺料数量上限。允许缺料不能放宽排除、时间或标签约束。
5. 每个用例的 `expected_recipe_ids` 列出**全量硬过滤匹配 ID**，不保证排名，也不受 `top_k: 3` 截断；推荐输出通常只展示前三个。因此全量 ID 适用于候选检索层断言，展示层应检查返回结果属于此集合，并遵守 top_k。
6. `structured/` 用例直接输入所给 `constraints`，隔离验证图检索；`nl/` 用例先解析 `question`，再与手工约束比较，并验证最终过滤结果。所有用例都给出约束，便于两层独立核对。
7. 无库存且未允许缺料的两个 NL 用例，业务层预期 `needs_clarification`；直接调用结构检索时没有匹配，其结构状态是 `no_match`。此差别用于检查补充信息提示，不能要求检索器凭空推断库存。

## 证据边界

菜名、步骤和时间为本项目人工设置的功能演示内容，未经过实做验证；不作营养、过敏安全或医疗宣称，也不能用这些示例替代实际饮食决策。调料不会自动省略；含禁用调料的菜谱应被过滤。

本目录用于本地演示、确定性约束回归和 NL 解析基线评测。它**不能当作真实用户项目数据、真实业务效果、原图谱质量或 LLM 泛化效果的证据**。规则解析器在这些题目上通过也只说明手工覆盖的范围；评价真实 LLM 需要独立模型运行、未参与实现的测试集和原始日志。

创建时已用独立子集/硬过滤逻辑核对 50 个手工预期集合，并检查 ID 唯一、分钟为正整数、主料与调料分离、来源 ID 一致和互斥辣度标签。
