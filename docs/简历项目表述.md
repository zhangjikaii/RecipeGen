# 简历项目表述

**RecipeGen 知识图谱与检索增强食谱问答系统**  
技术栈：Python、Neo4j、Cypher、BM25、E5、FastAPI、Pydantic、DeepSeek API。

- **项目介绍：**面向食材检索与烹饪问答，基于 5,898 条食谱与 44,802 个原始步骤构建 Neo4j 知识图谱，关联食谱、食材、步骤和来源；使用 FastAPI 提供食谱探索与多轮对话，接入 DeepSeek API 解析意图并判断是否检索。
- **检索与问答：**通过 Cypher 按所需及排除食材筛选完整候选池，在池内结合 BM25 关键词排名与本地 multilingual-e5-small 余弦排名进行 RRF 融合；回读食材、完整原步骤和来源构造有界上下文，由 DeepSeek API 重排并生成回答，校验食谱 ID、引用及来源。
- **实验结果：**基于原始食谱字段构造 32 条自动标注条件回归测试查询，在真实 Neo4j 上测得宏平均 Precision@10 78.44%、Recall@10 41.65%（DeepSeek 重排前）；完成检索消融核验与真实 API 问答流程验证。

## 说明口径

公开代码为 [GitHub 项目](https://github.com/zhangjikaii/RecipeGen)，方法见 [GraphRAG 设计](GraphRAG设计.md)，运行与评测范围见 [公开验收摘要](../reports/发布验收.md)。32 条 test 与 8 条 dev 分开，标签为原始字段字面自动标签；真实 API 结果为一次完整集成验证，不能声称全量人工语义或问答准确率。

三路候选包含 BM25、图谱先筛 E5 和完整图条件集合；图条件确定完整合法池，BM25/E5 在该池内进行双排名 RRF。图谱没有第三份排名。消融确认融合改变顺序与食谱集合，但当前自动条件标签没有证明融合优于单路。

食材是词典规则提及，不代表完整配方、用量或总烹饪时长；记录保留不同归档身份，未声称去重。图片及视频是基础归档清单，批处理保持停止，未完成全量视觉处理。旧 SQLite 演示的 20 条手工食谱及 50 条功能用例不能与真实测试图谱混用。

## 个人实现的边界

可围绕来源绑定、规则规范化、固定图条件查询、完整候选池评分与 RRF、图证据回读、有界上下文、API 输出校验与回退，以及实验协议讲述实现。Neo4j、FastAPI、Pydantic、E5 和 DeepSeek 是采用的工具与基础模型，没有训练或微调这些模型。

当前是包含意图路由的明确工作流，不宣称开放式自主规划、多智能体调度、通用多跳推理或社区摘要。未做独立评测的推荐准确率、引用准确率提升、响应性能、生产部署及企业用户规模不填写。后续新增效果结论需要相应标签、分母与运行证据。
