# 简历项目表述

## 当前可使用的项目描述

**RecipeGen：基于知识图谱的食谱检索与生成系统**  
技术栈：**Python、Neo4j、Cypher、FastAPI、Pydantic、MLX**。真实测试图谱检索、默认原步骤生成及一次本地模型选择功能检查已通过，语义效果尚未评测。

- 基于 RecipeGen 两个官方测试归档处理 **5,898 条分来源菜谱记录、44,802 行有序步骤**，构建 **159,040 个节点、425,687 条关系**的 Neo4j 基础图谱，保留来源 ID、原文与数据版本，完成原生回读核验。
- 实现参数化 Cypher 只读检索与 FastAPI 接口，支持中英文食材规范化、否定食材提及排除、菜谱详情及关系子图；返回规则提及证据、原始步骤与归档来源，验证真实图谱搜索、排除和详情流程。
- 实现基于图谱证据的食谱回答流程，支持程序选择与本地模型选择已知菜谱/证据 ID，再组织原始步骤与引用；检查 ID、步骤来源和引用，实际 Neo4j 读取与本地模型调用的功能校验通过。

简历篇幅有限时，可保留前后两条并链接仓库。以上数据量是图谱规模，不是推荐准确率；默认 `grounded` 由程序组织原文，本地模型只选择已有记录，不能写成已验证的自由配方生成能力。

## 证据与方法边界

2026-10-04 的 [发布验收摘要](../reports/发布验收.md)记录真实 Neo4j 状态、番茄/鸡蛋搜索、否定食材排除、详情子图与生成校验。该次生成 `grounded`、`llm_called=false`。方法与复现见 [食谱检索与生成系统](食谱检索与生成系统.md)。

可选 `local` 模式已完成一次 [发布验收摘要](../reports/发布验收.md)：使用 `mlx-community/Qwen3-VL-2B-Instruct-4bit`，实际调用且未回退，已知菜谱/证据 ID 选择与原步骤来源校验通过。模型只选择已有记录，程序组织最终回答；该次输入为文本，没有调用图像识别。**不据此填写语义准确率、推荐效果或响应性能指标。**

基础图谱关联 **46,553 张图片、1,512 个视频的归档元数据**，保留部分已经运行的视觉观察候选。图片和视频批处理保持停止，未完成全量视觉处理；视觉数量、结构回读与候选对齐不等于语义准确率。

食材是原步骤中的词典规则提及，不代表完整配方；缺少完整结构化用量和总烹饪时长。记录保留不同归档身份，未声称跨归档去重。提及排除不能写成已验证的库存匹配、忌口或过敏安全保障。

旧 SQLite / `RG*` 兼容演示使用 **20 条手工菜谱**，早期 **50 条人工功能回归通过**；可独立说明，不能与真实 5,898 条测试记录或真实模型效果混用。

## 面试时说明个人实现

可围绕三个环节讲述：从官方测试归档保留文本、媒体成员及来源身份；设计固定构建范围的只读查询和别名/否定处理；将原步骤与可解析引用组织为回答，为模型选择设置 ID 校验和失败回退。

Neo4j、FastAPI、Pydantic 与模型运行框架是使用的工具；数据读取与来源记录、领域规范化规则、查询范围约束、证据组装和校验流程是项目实现。当前采用显式工作流，没有模型自主规划或多智能体调度。

未运行独立对照或评测前，不写推荐准确率、引用准确率提升、复杂多跳推理效果、生产级部署或企业用户规模。可展示 README、真实 API 演示、数据来源与验收报告；新增指标须另附分母、运行设置及结果文件。
