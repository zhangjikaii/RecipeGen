# RecipeGen 多模态语义处理（历史可选扩展）

**图片和视频批处理均保持停止，未完成全量处理。** 当前默认网页问答使用原食谱文本、食材提及和来源，不将视觉观察输入 DeepSeek。本文介绍保留的多模态扩展代码与历史单样例验证，不表示克隆仓库即有模型、媒体或数据库观察。

固定数据源为 `RUOXUAN123/RecipeGen` 的 `test.zip`、`test-video.zip`，revision `2506260d8cb193ecdb18ac31fc725ffec43f6602`。基础归档目录有 46,553 张图片、1,512 个视频，5,898 条 Recipe 保留不同归档身份。媒体目录定位不等于完成下载、识别或语义标注；没有食谱关联的孤媒体保留独立来源，不创造菜谱。

历史开发机器曾运行真实本地图像推理、CLIP 编码和单菜谱闭环，原始检查点及运行输出留在本地。公开范围见 [发布验收摘要](../reports/发布验收.md)。这些样例与已入库观察不能证明全量覆盖或语义准确率。

## 模型与方法

| 用途 | 历史固定配置 |
|---|---|
| 视觉语言模型 | `mlx-community/Qwen3-VL-2B-Instruct-4bit`，revision `9c4f5209e57b31f4b9dfba735de3fb983739c9cc` |
| 本地视觉推理 | `mlx-vlm==0.3.9` / `mlx==0.29.3`，Apple Silicon MLX |
| 跨模态向量 | `openai/clip-vit-base-patch32`，revision `3d74acf9a28c67741b2f4f2ea7635f0aaf6f0268`，512 维 |
| 向量环境 | `transformers==4.57.1`、`torch==2.8.0`、`torchvision==0.23.0` |

模型能力来自 [Qwen3-VL 模型卡](https://huggingface.co/mlx-community/Qwen3-VL-2B-Instruct-4bit)、[MLX-VLM](https://github.com/Blaizzy/mlx-vlm/tree/v0.3.9)与 [CLIP 文档](https://huggingface.co/docs/transformers/v4.57.1/model_doc/clip)，没有训练或微调基础模型。此本地 Qwen 是历史视觉扩展，当前网页问答 LLM 使用 DeepSeek API。

```text
固定测试来源与原图谱身份
 → 原媒体取回及 ZIP CRC / SHA-256 验证
 → 图像，或视频真实帧窗口 → VLM 原始输出
 → CLIP 编码原步骤、图像、真实帧
 → 余弦步骤候选，视频加入时间单调约束
 → 来源及扩展合同检查 → Neo4j 幂等追加 → 只读回验
 → 保存检查点、覆盖与失败 → 清理该任务临时媒体
```

视频按 5 秒窗口选取最多 3 个不同真实帧，保留 PTS、time_base 与文件哈希；不足帧数时记录实际数量，不复制帧。窗口向量取帧向量均值并归一化；同视频窗口使用动态规划维持步骤顺序，允许多个窗口指向同一步。余弦阈值、未通过、时间冲突和无步骤都记录为状态，不等于人工时间标注准确率。

模型结构有效但缺少 caption 时，保留单独请求短描述的恢复路径及原始输出；其他 JSON 错误按失败处理，不能把对象列表拼造描述。未知关系谓词保留在 JSON，不直接变成任意数据库关系类型。

## Neo4j 保存范围

| 扩展节点 | 内容 |
|---|---|
| `VisualObservation` | caption、原始 JSON、512 维向量、模型及来源 |
| `VisualObject` | 模型对象候选及可用 bbox |
| `VideoClip` | 视频来源、窗口及观察 |
| `Frame` | 真实时间戳、帧与哈希 |
| `SemanticRun` | 运行、模型、配置与批次身份 |

`HAS_OBSERVATION`、`HAS_CLIP`、`HAS_FRAME`、`BEFORE` 表示来源及时间结构；`DEPICTS`、`SHOWS_ACTION`、`ALIGNED_WITH` 和空间关系保留为模型候选。bbox、相似度与模型文本不是真值或校准概率；候选内容保留 `verified=false`。

扩展要求固定标签及关系、同 test/build/revision 和真实媒体来源，拒绝悬空端点、身份不符及同运行 ID 的冲突。原事实只读，扩展稳定 ID 幂等追加。回读 `verified` 只说明结构、身份和来源核验，不证明模型语义正确。详情可显示已有观察，缺少可核验排序时间时标为 `latest_unverified`。

## 可选本地运行

基础 Neo4j 图谱与连接需先自行重建，模型、媒体和原始检查点不随源码发布。仅在需要主动复现历史视觉扩展时准备 Apple Silicon 环境与 `ffprobe` / `ffmpeg`：

```bash
python3 -m venv --system-site-packages .venv-mm
.venv-mm/bin/python -m pip install -r requirements-multimodal.txt
.venv-mm/bin/python scripts/download_multimodal_models.py
.venv-mm/bin/python scripts/run_multimodal_pipeline.py --recipe-id '<recipe_id>' --import-neo4j
```

运行入口默认遵循检查点及资源边界；全量或图片专用批次的参数见对应脚本 `--help`，发布操作和网页启动不会执行这些命令。签名相同的有效观察可显式复用，但须重新计算对齐并核验入库，不能复制成功状态或旧结论。

持久产物位于 `data/multimodal/runs/`，临时媒体位于 `data/multimodal/work/`；模型在 `.runtime/`。成功观察和对齐可无损 gzip，仍需检查总体剩余空间。清理后历史文件路径不表示原媒体仍可打开，来源、CRC、哈希与模型输出继续留在本地检查点。

```bash
.venv/bin/python scripts/verify_multimodal_progress.py --neo4j --output reports/multimodal-progress-audit.json
.venv-mm/bin/python scripts/query_multimodal_graph.py --query 'cutting tomatoes in a pan' --limit 5
```

独立审计检查原媒体 ID 覆盖、证据及当前数据库；`current_scope_verified=true` 只表示选定范围通过，`completed_full_scope=true` 还需全量覆盖。离线报告不能替代当前数据库读取。可选查询 `--llm` 是本地 YES/NO 实验，不属于当前网页问答；其成功或失败不能宣称推荐收益。

下载、解码、推理、编码、对齐、导入和回读各自记录失败；缺少阶段不能伪造后续成功。原媒体关联、观察候选与 `ALIGNED_WITH` 均不构成精确步骤标注。新扩展效果需另外构建人工标签与独立评测。
