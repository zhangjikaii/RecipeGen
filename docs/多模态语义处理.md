**本文保留开发机器的历史多模态方法；图片、视频批处理已全部停止，全量处理尚未完成。** 全量目标曾是固定测试集中的 46,553 张图片和 1,512 个视频，公开范围见 [发布验收摘要](../reports/发布验收.md)。仓库不附媒体、模型权重或多模态运行检查点；文中命令只供显式复现，不表示任务当前运行。全量完成还需独立审计同时确认原媒体 ID 覆盖、每项入库证据及当时数据库统计；单菜谱或部分媒体成功不能代替该条件。

历史批次曾改为仅处理图片，保留已入库的旧视频观察；随后图片批次也被停止。图片批次的设计是只复用有来源的图像观察，再对原文本步骤对齐和核验入库，不下载视频成员、不抽帧、不调用视频窗口推理。图片全量通过时才使用 `completed_image_scope=true`，`completed_full_scope` 仍要求完整多模态范围；目前没有全量完成结论。

真实单菜谱闭环已完成：**3 张图片、1 个视频、2 个连续窗口、6 个实际帧、5 条视觉观察、5 条步骤对齐候选**，追加 29 个节点和 59 条关系。见 [发布验收摘要](../reports/发布验收.md)。[发布验收摘要](../reports/发布验收.md) 确认当前范围通过，基础图谱 7 项检查与扩展检查通过，`completed_full_scope=false`。

[发布验收摘要](../reports/发布验收.md) 返回 3 条带原步骤和来源的结果，`read_only=true`、`llm_called=false`。[发布验收摘要](../reports/发布验收.md) 已实际逐项调用模型判断相关性，原始 YES/NO 输出与对应 ID 全部保留；该样例返回 `no_match`，不能包装成检索质量提升。短文本正负例探针分别返回 YES/NO，仅证明接口行为，不代表准确率。默认检索保留 CLIP 候选。

人工抽查该样例的视频末段可见水果碗，与关联的姜奶茶步骤并不完全一致。原媒体关联按数据集保留，`ALIGNED_WITH` 继续作为候选，不能把原 Recipe→Video 关联或相似度阈值理解为精确步骤标注。

预训练模型与推理能力来自 [Qwen3-VL MLX 模型卡](https://huggingface.co/mlx-community/Qwen3-VL-2B-Instruct-4bit) 和 [MLX-VLM v0.3.9](https://github.com/Blaizzy/mlx-vlm/tree/v0.3.9)。CLIP 将文本、图像投影到同维空间，项目使用归一化向量的余弦相似度，接口依据 [Transformers 4.57.1 CLIP 文档](https://huggingface.co/docs/transformers/v4.57.1/model_doc/clip)。本项目没有训练这些基础模型。

## 处理链路

```text
固定 test 来源与原图谱索引
  → 按菜谱取回原媒体，核验 ZIP CRC / SHA-256
  → 视频按 5 秒窗口选取最多 3 个不同的真实解码帧
  → 图像 / 连续帧窗口实际调用 VLM，保留原输出
  → CLIP 编码原步骤、图像、帧；窗口向量取帧向量均值并归一化
  → 余弦候选检索＋同视频时间单调约束
  → 来源与扩展合同验证 → Neo4j 追加写入 → 只读回验
  → 保存结果、检查点与覆盖统计 → 清理该菜谱临时媒体
```

视频帧以实际 PTS / time_base 为证据；窗口和对齐使用相对首个解码帧的秒数，原始时间戳另行保存。短窗口不足 3 个不同帧时明确记录数量，不能复制帧伪造覆盖。超出资源上限、解码失败或缺少步骤时保留状态，不补造帧、动作、向量或文本。

模型返回合法对象/动作结构但漏掉 caption 时，对同一原图或同一组视频帧单独请求短描述；两次实际输出、输入哈希及生成参数全部保留。不会用对象列表拼造描述，其他 JSON 或结构错误仍按失败处理。[发布验收摘要](../reports/发布验收.md) 已通过，这只证明漏字段恢复链路可运行。

单图使用余弦阈值选择原步骤候选；同一视频的窗口按真实时间排序，通过动态规划保持步骤顺序单调，允许多个窗口指向同一步。阈值、未通过阈值、时间冲突和无步骤都写入结果；对齐只是候选，没有人工时间标注支撑的准确率。

## Neo4j 中保存什么

现有图谱节点通过 `kg_csv_id` 和固定构建身份引用；扩展节点采用 `RecipeGen` 标签与独立运行身份，每个菜谱有自己的 `run_id`，所属批次记录为 `pipeline_run_id`。

| 扩展节点 | 保存内容 |
|---|---|
| `VisualObservation` | 实际 caption、模型原始 JSON、512 维向量、模型名称/版本和来源 |
| `VisualObject` | 模型输出的对象候选及可用 bbox |
| `VideoClip` | 真实视频来源、窗口起止时间和窗口观察 |
| `Frame` | 抽取帧、实际 PTS、相对时间与文件哈希 |
| `SemanticRun` | 运行、配置、模型与批次身份 |

`HAS_OBSERVATION`、`HAS_CLIP`、`HAS_FRAME`、`BEFORE` 表示来源/时间结构；`DEPICTS`、`SHOWS_ACTION`、`ALIGNED_WITH` 与空间关系等保留模型候选语义。未知谓词保留在原始 JSON，不能直接变成任意数据库关系类型。caption 中出现一个名称不足以创造视觉关系，需对应模型对象/动作或原始关系输出。

**生成 bbox 是模型估计，`similarity_score` 是检索/对齐分数，二者都不是人工标注真值或校准概率。** 生成模型的 `confidence=null`，候选保留 `verified=false`。旧 Image / Video 的目录快照和 `recognition_status` 不被新结果覆盖，实际识别信息记录在新观察节点。

导入只允许固定标签/关系、同 test/build/revision、真实媒体与 Source 绑定；拒绝悬空端点、来源不符及同一运行 ID 的内容冲突。已有事实只读取，扩展按稳定 ID 幂等追加。写入后的 `verified` 状态仅表示 ID、来源、属性、端点和时间结构回读通过，不能解释成模型内容正确。

## 运行与续跑

使用独立模型环境；原 FastAPI 演示的 `.venv` 单独保存。本机已准备 `.venv-mm`，版本见 [固定依赖](../requirements-multimodal.txt)。换机时可在 Apple Silicon 上准备：

```bash
python3 -m venv --system-site-packages .venv-mm
.venv-mm/bin/python -m pip install -r requirements-multimodal.txt
.venv-mm/bin/python scripts/download_multimodal_models.py
```

另需可执行的 `ffprobe` / `ffmpeg`，以及已经核验的 Neo4j 基础图谱；连接复用本机私密活动配置。全量按持久运行目录保存签名、状态和每项处理证据，不要求把约 44 GB 的两个原始 ZIP 全部下载到本机。

全量命令（默认从已有检查点续跑）：

```bash
.venv-mm/bin/python scripts/run_multimodal_pipeline.py --limit 0 --import-neo4j
```

历史图片专用批次的启动命令（新机器没有该旧运行检查点）：

```bash
.venv-mm/bin/python scripts/run_full_multimodal_batch.py --modality images \
  --reuse-run mm-f29d9954f11db9115fb7
```

后续使用同一 `--modality images` 从自己的检查点续跑。签名记录 `processing_modalities=["image"]`，期望视频数为 0；仍核验完整原数据来源，图片执行覆盖包括全部原菜谱与 9 张孤图。旧视频记录不会作为图片成功项计数。

历史批次使用带结束审计的脚本 `scripts/run_full_multimodal_batch.py`。它完成或因资源限制停止后，自动运行独立 Neo4j 审计，保存 `reports/multimodal-full-audit.json` 和 `reports/multimodal-batch-result.json`。这些文件由自己的运行生成，仓库没有后台任务；启动本身不表示完成。全量启动还会核对 Recipe/Image/Video 的完整 ID 集合等于原图谱，拒绝漏选、重复来源或空集合造成的虚假完成。

修复推理代码后，新批次可显式复用旧批次的有效观察，继续计算对齐并重新核验入库：

```bash
.venv-mm/bin/python scripts/run_full_multimodal_batch.py \
  --reuse-run mm-e9b41c27cc32b8c8b509
```

复用要求相同原始构建、测试来源、模型版本和媒体抽取配置，并逐项检查输入身份、哈希、原响应及 512 维向量。只复制有效观察并附来源证据，不复制成功状态、对齐或入库结论；详情保存在新批次的 `reuse-report.json`。本次重启复用了 6 项缓存中的 81 条观察，拒绝数量为 0。

单菜谱核查，将 `<recipe_id>` 换成原图谱中的实际 ID；仅需要现场查看样例媒体时保留文件：

```bash
.venv-mm/bin/python scripts/run_multimodal_pipeline.py \
  --recipe-id '<recipe_id>' --import-neo4j --keep-media
```

`--run-id` 可指定批次身份；默认续跑不能理解为重新覆盖同 run 的不同内容。模型/抽帧/配置发生改变时应记录新的运行身份。`--min-free-gb 1.5` 为默认剩余磁盘门槛，资源不足必须记录失败或暂停，不能把截断处理写成完成。

独立覆盖审计默认仅读取公开数据与检查点；显式加 `--neo4j` 才读取私密连接配置，并执行固定只读 Cypher：

```bash
.venv/bin/python scripts/verify_multimodal_progress.py --neo4j \
  --output reports/multimodal-progress-audit.json
```

单菜谱审计可追加相同 `--recipe-id`。`current_scope_verified=true` 表示当前选定范围通过，`completed_full_scope=true` 还要求所有 5,898 条原 Recipe 和 9 条孤媒体全部通过。离线审计不会把历史入库报告当作当前数据库实测；全量未完成时保留 `status=incomplete`。退出码 0 只表示当前选定范围通过，离线或当前范围未通过时为 1。

跨模态查询入口支持英文需求，例如：

```bash
.venv-mm/bin/python scripts/query_multimodal_graph.py --query 'cutting tomatoes in a pan' --limit 5
.venv-mm/bin/python scripts/query_multimodal_graph.py --query 'cutting tomatoes in a pan' --limit 5 --llm
```

查询只覆盖已经成功入库的观察；`--llm` 才请求本地模型逐项给出 YES/NO，由程序绑定已有观察 ID，返回原步骤与来源；无效模型输出会报错，不补造选择结果。可用 `--output` 保存报告。实际入库、检索与模型选择的结果分别保存，模型判断质量仍需评测。

## 磁盘与失败边界

- 模型缓存：`.runtime/model-cache/`；模型配置：`.runtime/multimodal-models.json`。
- 成功项的 `prepared.json` / `observations.json` / `alignment.json` / `bundle.json` 自动无损 gzip 为 `*.json.gz`，续跑可直接读取；`import-report.json`、`state.json`、进度报告仍为普通 JSON。压缩保留原响应与向量证据，但不能消除全量 Neo4j 数据和持久结果的磁盘需求。
- 临时原件与抽帧：`data/multimodal/work/`，按菜谱处理后只删除该任务拥有的目录。
- 持久运行：`data/multimodal/runs/<pipeline_run_id>/`，保存签名、状态及各项识别/对齐/入库报告。
- 持久识别输出、向量、检查点与进度另行保存；临时目录上限不代表全部产物不会增长，需同时检查剩余磁盘。
- 清理后的媒体 `path` 是历史处理位置，**不代表仍可打开**；原始成员身份、CRC、SHA、PTS、模型输出与清理状态继续保留。
- 下载、解码、模型解析、向量计算、对齐、入库及回读分别记录失败。缺少阶段的结果不能伪造后续成功，续跑依据检查点继续未完成项。

## 自己实现与调用库的边界

| 调用现成能力 | 项目实现 |
|---|---|
| MLX-VLM / Qwen3-VL 推理 | 多图窗口输入、输出合同检查、原始输出与版本证据保存 |
| Transformers / CLIP 编码 | 向量规范化、窗口聚合、候选排序、时间单调对齐与拒绝条件 |
| HTTP、ZIP、ffprobe / ffmpeg | 固定来源、Range/CRC/SHA 验证、真实帧选择、资源限额和临时文件清理 |
| Neo4j 驱动 | 原图谱索引复用、候选 schema、来源绑定、幂等追加、原事实保护和回读核验 |

运行覆盖是工程进度；来源/结构检查是可追溯性证据。语义正确性仍需独立人工标注和评测，测试集构图与识别运行不能包装成 held-out 模型性能。
