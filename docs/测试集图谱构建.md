# RecipeGen 测试集图谱构建与复现

**源码发布说明：**本文保留基础阶段的构建方法和 2026-10-02 历史规模。仓库不附 `data/test_graph/` 的语料、清单、CSV、报告或数据库，下面的命令在本机生成这些产物。后续文本检索见 [GraphRAG 设计](GraphRAG设计.md)，公开历史结果见 [发布验收摘要](../reports/发布验收.md)。第三方数据授权须按来源核对，本次源码发布未做授权审核。

## 本轮完成范围

数据范围固定为官方 RecipeGen 数据集的 **`test.zip` 与 `test-video.zip`**，不读取训练或验证归档。构建以相同、不可变的 Hugging Face 数据集提交为准，保留两个归档中的独立记录，**不跨归档去重**。

这里的“完整测试集”包括：完整清点两个 ZIP 的原始成员目录，读取所有原有 `goal.txt` / `steps.txt`，保留缺失文本记录，并为全部被清点的图片/视频成员生成带来源的元数据节点。**没有下载完整图片/视频负载，也没有进行视觉内容识别。**

先核对 `data/test_graph/manifest.json` 的 `status=complete` 与 `complete_test_scope=true`，再核对两份归档清单的完整状态。图谱规模、实际抽取概念数量与导入核验结果以本次生成的报告为准；不要用内置词典大小替代实际抽取数量。

## 方法与教程对应

基础阶段实现参考《多模态知识图谱构建方法》中的最小构建顺序；下表仅记录基础阶段，后续部分多模态运行见 [多模态语义处理](多模态语义处理.md)，文本 GraphRAG 见 [GraphRAG 设计](GraphRAG设计.md)：

| 教程阶段 | 本轮实现情况 |
|---|---|
| V1：Recipe / Ingredient / Step / Image 路径 | 保留原始菜谱文本与步骤；Ingredient 是步骤词面候选；Image / Video 是归档成员元数据 |
| V2：Action / Tool / Time / Temperature | 离线词典与规则候选抽取，保留原步骤、命中跨度和方法标记 |
| V3：图像 Caption / VisualObject / VisualRelation | **未运行** |
| V4：VideoClip / Frame / 视频动作 / 时序关系 | **未运行**；仅有 Video 文件成员节点 |
| V5：跨模态语义对齐 / embedding / RAG | 未进行跨模态语义对齐；目录关联不能代替语义对齐 |

`NEXT_STEP` 表示原始文本步骤顺序，不是视频时间轴。图片与菜谱、视频与菜谱的关联只基于经过清点的归档目录身份，保留 `directory_membership_only`，不能据此声称某张图展示了某一步。

## 构建链路

```text
固定数据集提交＋test 归档白名单
       ↓
HTTP Range 清点 ZIP 中央目录
       ↓
读取全部原始文本成员，核验大小 / CRC / SHA
       ↓
来源明确的 records.jsonl＋媒体成员清单
       ↓
文本规则候选抽取＋Step / Source / 媒体节点
       ↓
图谱 JSONL、CSV 与构建报告
       ↓
CSV 离线校验
       ↓
导入本地 Neo4j → 数量与关系回读核验 → 查询
```

HTTP Range 请求要求服务器返回精确的 `206` 与 `Content-Range`；拒绝将服务器返回的整包内容当成小范围读取。文本读取有缓存和检查点，失败时保留进度以便继续。媒体清单记录文件大小、压缩大小、CRC 与原始成员路径；这验证了目录信息，**不代表已经对每张图片或每个视频的内容完成解码/CRC 核验**。

## 从项目目录复现

先按 README 准备 Python 虚拟环境并安装依赖。以下命令在 `recipegen` 项目目录运行；macOS / Linux 可以使用 `.venv/bin/python`，Windows 可以使用 `.venv\Scripts\python.exe`。

### 1. 读取指定测试归档

```bash
python scripts/build_test_corpus.py \
  --archives test.zip test-video.zip \
  --revision 2506260d8cb193ecdb18ac31fc725ffec43f6602 \
  --output-dir data/test_graph
```

固定提交来自本轮实际来源清单，复现时保留它；如果明确要构建另一版本，应记录新提交并作为另一个构建。默认的下载预算针对 Range 字节而不是整包；不要求下载整份媒体归档。

检查：

- `data/test_graph/manifest.json`：范围、提交、状态、记录数与记录文件哈希。
- `data/test_graph/source/test.manifest.json` 和 `test-video.manifest.json`：归档成员分类、全部文本成员完成情况、实际网络读取与缓存状态。
- `data/test_graph/source/*.members.jsonl`：原始成员身份与媒体元数据。
- `data/test_graph/source/*.texts.jsonl`：原文与 SHA、编码、归档来源。
- `data/test_graph/records.jsonl`：来源记录，保持两个归档记录身份独立。

源归档中的两个 `goal.txt` 有内容但没有 `steps.txt` 的记录，仍保留标题与空步骤；不补写烹饪步骤。孤立图片目录的 9 个图片也保留 Image 与 Source，不凭目录名称创造缺失菜谱。这些质量情况应同时出现在来源清单和最终构建报告中。

### 2. 构建图谱文件

```bash
python scripts/build_test_graph.py \
  --records data/test_graph/records.jsonl \
  --output data/test_graph
```

输出：

| 文件 | 内容 |
|---|---|
| `nodes.jsonl` | Recipe / Ingredient / Step / Action / Tool / Image / Video / Source 节点 |
| `relationships.jsonl` | 文本候选关联、步骤顺序、来源和媒体目录关联 |
| `extraction_evidence.jsonl` | 每条原文提及、字符跨度、步骤号、来源和抽取方法 |
| `media_associations.jsonl` | 每个媒体成员的目录关联结果与关联方法 |
| `neo4j_import/nodes.csv` | 带 JSON 属性的节点 CSV |
| `neo4j_import/relationships.csv` | 带 JSON 属性的关系 CSV |
| `build-report.json` | 固定提交、构建身份、输入/代码哈希、实际数量、缺失与关联情况 |

`build_id` 由固定提交、构建格式、输入与代码版本派生。更改词典或构建代码后应重新构建、保留新报告，不覆盖旧结果的解释。

### 3. 离线校验 CSV

```bash
python scripts/import_test_graph_neo4j.py \
  --nodes data/test_graph/neo4j_import/nodes.csv \
  --relationships data/test_graph/neo4j_import/relationships.csv \
  --validate-only
```

此步骤校验 schema 白名单、同一 test split / 固定提交 / 构建身份、唯一 ID、关系端点和 Source 信息；**不读取 Neo4j 凭据，不连接数据库**。

### 4. 在新建独立空库复现导入

开发机器曾使用 Neo4j Desktop 实例（`127.0.0.1:7687`）并完成标签迁移，历史方法见 [Neo4j 部署记录](用户Neo4j部署.md)。新机器需提供自己的实例；现有 Neo4j 可在项目 `.env` 配置 `NEO4J_*` 后运行 `python scripts/import_test_graph_neo4j.py`，实际结果保存为自己生成的报告。下面的安装命令是 macOS ARM64 上准备**新建独立空库**的可选路径。已有旧标签节点的实例不能直接按新标签再导入，否则可能产生重复节点，应先单独迁移并核验。不要为复现删除已有数据库。

本轮早期使用项目本地 **Neo4j Community 5.26.31＋Java 21**。运行时放在 `.runtime`，与系统安装隔离。启动脚本使用本机生成且不打印的随机凭据；运行时和凭据不进入项目公开打包。换一台电脑时需准备对应平台的运行时，不能直接假定当前 macOS ARM 安装可用于其他平台。

macOS ARM64 首次安装项目本地运行时（安装包版本与 SHA-256 固定在脚本中）：

```bash
python scripts/setup_local_neo4j.py
```

终端 A：

```bash
python scripts/local_neo4j.py console
```

终端 B，确认数据库已经启动：

```bash
python scripts/local_neo4j.py import-graph
```

若用于复现的空库已在运行，不需要再次启动。该安装只监听本机：Bolt `127.0.0.1:8767`，Browser [127.0.0.1:8744](http://127.0.0.1:8744/)。启动网页时使用自己实际选择的数据库连接，不混用端口，也不要默认已有实例为空。

导入为**真实数据库写入**：现行公共标签使用 `RecipeGen`，构建管理标签使用 `RecipeGenBuild`，仍以构建身份和 `split=test` 限定范围，保留旧构建，不删除已有图谱。用户指定实例的本次标签迁移已核验；历史 JSON 保留导入当时的标签。导入后回读验证数量与端点，记录实际运行的报告。离线 CSV 校验成功不能代替实际导入成功。

### 5. 查询与追溯

```bash
python scripts/query_test_graph.py --config .runtime/local-neo4j.json --query tomato
```

查询示例用于检查食材候选、对应菜谱、原始步骤与来源。查询模式必须说明是词面候选检索，不能因为查到了 `tomato` 就断言用户库存满足了完整配方。

完成后可停止项目本地数据库：

```bash
python scripts/local_neo4j.py stop
```

## 图谱事实与候选必须分开

- Recipe 标题、Step 原始文本与顺序、Source 成员身份来自实际读取内容。
- Ingredient / Action / Tool 是词面候选；相关关系带 `verified=false`、`semantics=text_mention_candidate`，Recipe 的配料完整性为未确认。
- `do not add salt` 也可能命中 `add` 与 `salt`；可选材料、否定表达和实际用量没有被词典可靠理解，不能把候选关联当成确定使用事实。
- Duration / Temperature 保存 Step 中的原始命中字符串，包括范围和单位；缺失为未知，**不把步骤时间相加推算菜谱总时间**。
- 媒体节点标记 `metadata_only` / `recognition_status=not_run`；目录关联不证明图片内容、视频动作或步骤对齐。
- 这批图谱与演示项目的严格库存筛选分开；不将不完整的规则食材表直接投入“库存齐全”验证。

抽取细节与已验证规则契约见 [测试集文本抽取](test-graph-extraction.md)。

## 怎样报告结果

本轮[发布验收摘要](../reports/发布验收.md)已通过，失败项为 0：全部 44,802 Step、244,427 提及证据与 11,794 文本来源 SHA 一致。Step 按已记录规则去除每行首尾空白，30,433 行完全原样，14,369 行仅做该规范化；该检查不评估语义抽取准确率。

至少区分：两个归档是否完整清点、文本成员是否读取完成、原始记录数量、实际图谱节点/关系数量、实际提及与规范化概念数量、媒体是否只读取目录、CSV 校验、Neo4j 实际导入和回读、抽取人工核查。

**没有跨归档去重，记录数量不能称独立去重菜谱数量。** 同一来源版本完整构图不等于识别准确率。测试集被作为本次构建输入，不能把这一过程包装成模型在 held-out 测试集上的评测；若后续训练或调参，需要重新设计独立的评估边界。
