# RecipeGen 官方文本格式与最小导入

**阶段说明：**本文记录最初 5 条官方文本的试读。两个完整测试归档的构建、媒体目录清点与真实 Neo4j 验证，见 [测试集图谱构建](测试集图谱构建.md)。

初始阶段只获得技术教程，未获得旧工程与 Neo4j 存储。教程里的 `title / ingredients / instructions` JSON 是假设示例，不能当成官方数据 Schema。后续工程根据实际归档格式重新构建；当前节点与关系见 [图谱 Schema](图谱Schema.md)。

2026-10-02 核对的官方入口：[Hugging Face 数据集卡片](https://huggingface.co/datasets/RUOXUAN123/RecipeGen)、[仓库文件目录](https://huggingface.co/datasets/RUOXUAN123/RecipeGen/tree/main)、[论文](https://arxiv.org/html/2506.06733v3)。

## 实际可访问文件

官方仓库根目录只有 README、Git 属性文件和八个大型 ZIP：`test.zip`、`test-video.zip`、`train-image1.zip`、`train-image2.zip`、`video1.zip` 至 `video4.zip`。最小的 `test.zip` 是 15,875,671,546 字节，不能为了几个文本样本整包下载。没有发现独立公开的文本 JSON/CSV 文件；Dataset Viewer 当前显示不可用。

卡片公开的每道菜目录结构为：

```text
recipe_directory/
  goal.txt       # 菜名
  steps.txt      # 步骤文本
  1.jpg ...      # 配图，不读取
  video.mp4      # 仅视频子集可能存在，不读取
```

图片编号、视频与步骤存在对应关系是官方数据用途，但本次只导入文本，不验证或重建多模态对齐。论文说明数据来自 Douguo、YouTube、YouCook2；单条原始网页 URL 是否随 ZIP 文本提供尚未确认，不能补造该 URL。

## 轻量读取方法

`scripts/import_recipegen.py` 只依赖 Python 标准库。远程模式先获取小型仓库元数据并固定 commit，再用 HTTP Range 读取 ZIP/ZIP64 目录；只打开 `goal.txt` 和 `steps.txt` 成员。服务器必须返回精确的 `206 Content-Range`，否则立即停止；默认累计 ZIP 字节预算 16 MiB，禁止无界读操作。**不下载完整 ZIP，也不读取任何图片或视频成员。**

```bash
python3 scripts/import_recipegen.py \
  --archive test.zip --limit 5 --max-download-mb 16 \
  --output /tmp/recipegen_official_text.json
```

如用户已有原始 ZIP，可通过 `--local-zip /path/to/test.zip` 仅取文本，不解压媒体。`--limit` 取按目录名排序的前 N 个完整文本对，是便于演示的便利抽样，不能当作随机、代表性或用于宣称泛化的测试集。

## 暂存格式与缺失字段

输出格式是 `recipegen-text-staging-v1`，使用 `records` 而不是当前应用的 `recipes`。稳定 ID 来自数据集、ZIP 名和目录的 SHA-256；来源保存 commit、ZIP 名、两个成员路径以及原文本哈希。原文本保留，步骤仅按原始非空行切分，不合成缺失步骤。

真实样本的菜名与步骤为英文。部分 ZIP 路径没有正确标记 UTF-8，Python 解码后会显示乱码；导入器保留用于精确定位的原始成员名，同时将可恢复的 UTF-8 路径存为 `recipe_directory_display`，只用于展示，不借目录里的“10分钟”等字样推断烹饪时间。

| 暂存字段 | 来源或处理 | 不能做的推断 |
|---|---|---|
| `name` | `goal.txt` 原文 | 不自动翻译、重命名 |
| `steps`、`raw_text` | `steps.txt` 非空行及完整原文 | 不凭空补步骤 |
| `ingredients: null` | 卡片未确认独立完整食材清单 | 步骤提到的食材不等于完整清单 |
| `seasonings: null` | 未完成主料/调料分类 | 不自动假设所有未提到调料可省略 |
| `minutes: null` | 未确认总烹饪时间字段 | 视频时长、单步时间不是总烹饪时长 |
| `tags: []` | 未做标签核验 | 不按菜名猜“素食”“不辣” |
| `source.url` | 官方 ZIP 的固定 commit 页面 | 不冒充原始用户菜谱页面 |

**暂存文件不能直接覆盖或混入 20 道手工演示图谱。** 当前应用若要求正整数 `minutes` 和完整主料，只能先保留这批文本用于“按菜名/步骤查找并引用原文”的功能。要支持库存、排除、时限推荐，需要后续明确的食材抽取、主料/调料区分、时间来源核验与人工审核；没有已知时间的记录不能通过 `max_minutes` 硬过滤，也不能写一个默认虚构时间。

## 许可与来源记录

Hugging Face 元数据标记 `cc-by-4.0`，同一数据集卡片正文却写 `CC BY-NC 4.0`；论文第 6 节也写 CC BY-NC 4.0，并要求注明来源。这里保留这项冲突，暂存文件不将其归并为确定的宽松许可。当前用途是本地非商业研究演示；要发布数据或用于商业交付，应先核实数据发布者的许可说明。

论文与卡片还出现 26,453 和 26,435 两种总菜谱数。导入报告只报告本次实际读取的文本对数，不以页面总数宣称已经处理整库。

## 当前验证记录

已在 2026-10-02 实际运行导入器并成功读取 5 道真实菜谱的文本，输出为 `/tmp/recipegen_official_text.json`。固定 commit 是 `2506260d8cb193ecdb18ac31fc725ffec43f6602`，读取的 `test.zip` 有 4,387 个完整 `goal.txt / steps.txt` 对；ZIP 共 61,162 个成员，中央目录 8,140,698 字节。

本次导入累计 44 个精确 Range 请求、8,143,905 字节 ZIP 目录与文本读取，**媒体成员读取数为 0**，没有下载完整 ZIP。五个菜名分别为 Egg Wrapped Dumplings、Cheese Army Stew、Braised Pork with Carrots and Bamboo Shoots、Shepherd's Purse Potstickers、Enoki Mushrooms in Tomato Sauce。它们证明真实文本可轻量读取，不证明完整食材图谱、时限推荐或多模态抽取已经完成。

另用内存中的手工局部 ZIP 验证只访问两个文本成员、忽略图片/视频、保留缺失字段、UTF-8/GB18030 解码；模拟响应验证 HTTP 状态、范围、长度不匹配和超出预算时拒绝读取。这个局部测试是导入器回归验证，不能计入真实数据量。

所有后续结果都应区分“官方文本导入”“手工示例检索”和“真实 LLM 调用”。
